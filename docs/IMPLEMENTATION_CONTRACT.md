# Common Ground local implementation contract

Decision 2026-10-28. Local-only complete fictional sample. No real accounts, deployment or external communications. This is a trusted-process same-machine demo: separate services and capabilities enforce HTTP permissions, but hostile same-UID code and the OS administrator can read files and are out of scope. SQLite is the durable local store; distributed deployment/PostgreSQL are future work.

## Ownership
- Lead: broker/, shared/schema.py, solver/checker, broker tests, exports, docs, scripts/run.py, provisioning and Python dependency files.
- Owner worker: owner_agent/, shared/protocol.py, tests/test_owner*.py and protocol tests. No broker/web edits.
- UI worker: web/, owner-web/, public/, package.json/lock, TypeScript/Vite configs, browser QA. No backend edits.
- Root: independent browser/privacy acceptance and final commit. No worker commits, CUA, PR, push or deploy.

## Ports, storage and authentication
Broker UI4301/API4302; Asha4311, Ravi4312, Leena4313. Bind 127.0.0.1. Owners serve dist/owner; broker frontend serves dist/broker. Runtime .runtime ignored. IDs: broker `common-ground-broker`, circle `dev-circle`, goal `dev-appointment`, date `2026-11-02`, timezone `Asia/Kolkata`.

NO COOKIES. Distinct ports do not isolate cookies. Each owner has a random pairing code in its own 0600 directory. The launcher writes local #pair= links into the private .runtime/pairing-links.json operator file and prints only that file path; broker API/config never receives owner pairing codes or session tokens. Owner UI consumes/clears fragment, POSTs pair_code to /api/session, retains only the returned short-lived token and expiry in its origin's localStorage and sends Authorization Bearer on /api requests. Strict owner Origin required on browser mutations; session requires actual secret, never localhost alone. No unauthenticated endpoint issues authority. XSS and hostile same-UID execution remain out of scope; ordinary cross-origin browser/API access is denied. Broker uses its own distinct session capability via same local pairing flow.

Provisioner creates .runtime/config.json holding broker session/pair secret, broker_ingest_token and owner public URLs plus narrowly scoped owner service_token values. Owner configs (inside owner directory): owner_id, port, broker_url, broker_ingest_token, service_token, pair_code, data_dir. Broker reads only common config; never opens owner dirs. Owner signing/encryption/session secrets are created inside owner service, permissions0600. Service capability cannot access private/session/signing/approval endpoints.

## Signed protocol
SignedMessage `{body,signature}` (base64url Ed25519). Body exact keys: `type,schema_version:1,message_id,issuer,audience:[...],circle_id,issued_at,expires_at,nonce,key_id,consent_revision,payload`. UTC ISO timestamps. Canonicalization RFC8785. Validate type, purpose, audience, expiry, key revocation, persisted unique nonces, monotonic consent revisions. Never publish private reasons or hashes of them.

ReleaseGrant payload: `{goal_id,goal_revision,purpose:'coordinate-appointment',retention:'Released facts remain in this local agreement audit; withdrawal stops future use.',recipients:{humans:['asha','ravi','leena'],broker:'common-ground-broker',inference:['fireworks']|[]},fields:['owner_id','capabilities','task_ids','start','end','capacity','preference_cost','constraint_revision'],offer:{offer_id,owner_id,revision,constraint_revision,capabilities:[...],task_ids:[...],start,end,capacity:1,preference_cost:0}}`. Minutes since midnight on scenario date. One released broad window plus task allowlist; private conflicts are rechecked locally. Envelope audience includes broker/human IDs and `fireworks` if granted. Family release never implies model authorization.

Approval payload `{proposal_id,version,proposal_digest,manifest_digest,action_ids,constraint_revision,execution_not_after,compensation_policy:'delete-only-unchanged-created-events'}`. Withdrawal payload `{goal_id,offer_id,reason_code:'availability_changed'|'preference_corrected'|'owner_withdrew'}` with strictly higher consent_revision. No broker route signs approvals.

shared/protocol.py API: `canonical(value)->bytes`, `digest(value)->hex`, `utc_now()->str`, `expires_in(seconds)->str`, `sign_message(private_key,body)->dict`, `verify_message(message,public_key,audience=None,message_type=None,now=None)->body` or ValueError, `new_identity(path,owner_id)->{private_key,public_key,key_id}`, `envelope(owner_id,key_id,message_type,payload,consent_revision,audience,ttl=3600)->body`. Public key accepts base64url raw or cryptography object. Shared schema validation in shared/schema.py.

## Task/proposal shape
Task `{task_id,label,capability,duration,earliest,latest,location,predecessors:[...]}`. latest means latest END. Five catalog tasks: prepare/preparation20 window12:20–13:00 home; outbound/driving40 window13:10–13:50 home→clinic; accompany/accompaniment90 window13:50–15:20 clinic; return/driving40 window15:20–16:00 clinic→home; handoff/handoff15 window16:00–16:20 home. Predecessors form this chain. Asha tasks prepare/handoff window12:00–16:30; Ravi outbound/return13:00–16:15; Leena accompany/return/handoff13:40–16:45, with a private conflict after16:45. Source private calendars/preferences remain local.

Assignment `{task_id,owner_id,start,end,offer_id,offer_revision}`. Action `{action_id,owner_id,task_id,label,start,end,date,timezone,adapter:'local-calendar',event_id,expected_absent:true}`. Proposal `{proposal_id,version,goal_id,goal_revision,date,timezone,created_at,expires_at,tasks,assignments,actions,offer_refs:[{owner_id,offer_id,revision,consent_revision,constraint_revision}],solver:{status,objectives,settings},checker:{valid,checks,errors},model_receipt_id:null|string,explanation}`. Immutable bare object. Proposal digest=digest(proposal); manifest digest=digest(proposal.actions). Wrapper may add these digests outside proposal.

## Owner HTTP
POST /api/session `{pair_code}` -> `{token,expires_at,owner_id}`. GET /api/session validates bearer. GET /api/state -> `{owner,preferences,private_calendar,release,consent_revision,constraint_revision,proposals,approvals,calendar_events,fault,skills,corrections}` only this owner's private data. POST /api/preferences `{expected_revision,availability_start,availability_end,task_ids,ask_before_driving,private_note?}` invalidates dependent offers/approvals and increments revisions. POST /api/release `{allow_inference:boolean,expected_revision}` builds exact preview-approved grant and publishes. GET /api/release-preview exact offer/recipients. POST /api/approve `{proposal_id,expected_version}` independently fetches immutable proposal, revalidates private constraints, signs/publishes exact manifest. POST /api/withdraw `{expected_revision}`. POST /api/fault `{mode:'none'|'timeout_after_write'|'fail_before_write'|'pause_before_send'|'conflict_before_write'}`. POST /api/calendar/{event_id}/edit `{summary}` labeled local user edit fixture. GET /api/calendar.ics authenticated owner export. GET /meta public `{owner_id,name,port,public_key,key_id,revoked:false}`.

Coordination endpoints: Authorization Bearer this owner's service_token; reject browser Origin. No vault/session/signing access. GET /coordination/status -> `{owner_id,consent_revision,constraint_revision,release,revoked_keys}` (released data only). POST /coordination/prepare `{proposal,approval}` -> `{reservation_id,fence,lease_expires_at,consent_revision,constraint_revision}`. POST /coordination/dispatch `{proposal_id,action_id,reservation_id,fence}` -> `{action_id,status,event_id,etag,verified_at,error?,intent?,remaining_effect?}` status VERIFIED/FAILED/AMBIGUOUS/PAUSED/CANCELLED/NEEDS_ATTENTION. POST /coordination/reconcile same request identifies deterministic existing event before resending. POST /coordination/compensate `{action_id}` conditionally removes only unchanged event. GET /coordination/events?proposal_id=... returns approved-action metadata only.

Approval/prepare check current private state, allowlist, intervals, revisions, expiry, exact manifest. Durable reservations exclude concurrent proposals; unique monotonic fences survive restarts. In one owner transaction validate revision, lease, action preconditions and persist dispatch authorization. Serialize withdrawal/send scheduling, recheck fence before transmission. Before intent withdrawal blocks; after intent cancels untransmitted request or reconciles/compensates. pause_before_send persists intent so the gap is testable. CalendarStore is separate SQLite with real durable event effects. Deterministic event IDs prevent duplicates. Ambiguous writes are read before retrying. ETag mismatch preserves user edits and yields NEEDS_ATTENTION.

## Broker HTTP
GET /health public. POST /api/session `{pair_code}` -> session token/expiry, Origin4301; GET validates. Every other /api request requires bearer. Browser mutations exact Origin4301. GET /api/state -> `{sample:true,goal,owners,offers,proposal,proposal_digest,manifest_digest,approvals,state,actions,model_runs,disclosures,history,revision,provider,planning}`. Initial state COLLECTING. owners `{id,name,role,accent,initials,url,key_id,public_key}`. offers are signed ReleaseGrant messages. approvals signed Approval messages. actions = action plus receipt status. model_runs are actual sanitized receipts. planning `{status,phase,error}`. POST /api/plan `{mode:'live'|'local',expected_revision}` async; local explicitly says structured workflow/no model. POST /api/execute `{proposal_id,expected_version}` prepare-all then dispatch with durable outbox. POST /api/reconcile `{proposal_id}`. POST /api/compensate `{proposal_id}`. POST /api/new-round `{expected_revision}` safely compensates preceding effects, preserves history, resets candidate. GET /api/evidence JSON portable sanitized proof. GET /api/agreement.ics approved assignments with verified/planned status. GET /api/events?after=... released durable event replay. No destructive reset unless coordinated.

Owner-to-broker routes require bearer broker_ingest_token: POST /v1/releases `{message}`, POST /v1/approvals `{message}`, POST /v1/withdrawals `{message}`. Full validation before ingestion. GET /v1/proposals/{id} -> `{proposal,proposal_digest,manifest_digest}`; GET /v1/current same wrapper or proposal:null. Ingest/service caps cannot call interactive API.
